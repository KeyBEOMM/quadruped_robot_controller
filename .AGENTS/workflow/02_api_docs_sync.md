# 02. API Reference Sync Workflow

로봇 하위 제어기 코드가 변경됨에 따라, 설계와 코드의 일치성(Single Source of Truth)을 유지하기 위한 강제 문서화 워크플로우입니다.

> **이 프로젝트의 단일 진실 참조 문서:** [`docs/API_REFERENCE.md`](../../docs/API_REFERENCE.md)

---

## 2.1. 동기화 트리거 조건

에이전트(사용자 포함)는 각 `Phase` 과정에서 **다음 항목 중 하나라도 발생하는 경우, 해당 커밋과 동시에** `docs/API_REFERENCE.md` 문서를 반드시 갱신해야 합니다.

| 변경(Event) 유형 | API Reference 갱신 대상 섹션 |
| :--- | :--- |
| **새 모듈/클래스/헤더 파일 추가** | 해당 모듈 섹션을 문단 통째로 신규 생성 및 포인터 추가 |
| **기존 함수 시그니처(Signature) 변경** | 기존에 작성된 함수 입출력 표 및 Data Types 표 갱신 |
| **`RobotParams` 수치 변경** | (예: 로봇 허벅지 길이, 조립 오프셋, 기구학적 제한값 변경 시) § `RobotParams` 표 수치 동기화 |
| **새 `RobotState` 추가/삭제** | § 핵심 상태 전이도(Mermaid 등) 및 조건표 최신화 |
| **네트워크 설정 변경** | § `CommTask` 등 설정 상수(UDP 포트, IP 등) 갱신 |
| **Phase 검증 완료** | § 데이터 흐름도의 `Phase N~` 주석 태그 삭제 및 Integration 반영 |

---

## 2.2. 무결성 규약

**"코드와 문서가 어긋난 상태로 다음 Phase에 진입하는 것은 엄격히 금지된다."**

1.  코드 구현이나 파라미터 튜닝이 완료되고 사용자가 "승인/좋아/반영해" 등의 확정 메시지를 남긴 즉시, 에이전트는 이 규칙에 따라 누락된 변경 사항이 없는지 스스로 스캔해야 합니다.
2.  `API_REFERENCE.md` 문서 내의 객체 지향 인터페이스 설명은 반드시 물리적 C++ 헤더 파일(`.h`)과 100% 동일한 형태와 의미를 가져야 합니다.
